# Chart Recommender

Raw 데이터의 구조와 사용자가 서술한 "보여주려는 목적"을 함께 분석해서, 가장 적합한 차트 유형을 근거와 함께 추천하고 실제로 시각화를 만들어주는 스킬입니다.

## 이 스킬의 핵심 원칙

1. **목적은 자유 문장으로만 받는다.** 사용자에게 "비교/추이/구성 중 고르세요" 같은 고정 카테고리를 절대 제시하지 않는다. 목적 문장은 그대로 두고, Claude가 내부적으로 해석한다.
2. **데이터 구조(필수 조건)가 의도(하고 싶은 말)보다 우선한다.** 아무리 목적 문장이 특정 차트를 암시해도, 데이터 구조상 그 차트가 성립 불가능하면 후보에서 제외한다.
3. **최종 결과물은 가로로 긴 화면(PPT/데스크탑 뷰)에 들어간다는 전제를 항상 반영한다.** 데이터·의도상 이론적으로 맞는 차트라도, 와이드 레이아웃에서 비효율적이면 감점하고 대체 차트를 우선 제시한다.
4. **애매한 임계치(카테고리 개수 등)는 고정 숫자로 사전 차단하지 않는다.** 대신 시각화를 만든 뒤 "라벨이 겹칠 수 있어 Top 10 + 기타로 묶었습니다" 같은 사후 코멘트로 처리한다.

## 실행 흐름

```
1. 입력 파악          → 파일이 있는가, 설명 텍스트만 있는가 확인 (분기)
2. 데이터 스캔        → 컬럼 프로파일링 → 구조 태그 판별 → 규모 지표 산출
3. 목적 문장 해석      → 의도 신호 추출 (복수 가능, 강도 판단)
4. 교차 매핑          → 데이터 구조(필수조건) ∩ 의도(보조조건) → 후보 압축
5. 레이아웃 필터       → 와이드 화면 적합도로 최종 순위 재조정
6. 추천 + 시각화 생성  → Top 1~2안 근거와 함께 제시, 실제 차트 렌더링
```

### Step 1. 입력 파악 (분기)

- **엑셀/CSV 등 실제 파일이 있는 경우** → `xlsx` skill(또는 해당 파일 형식의 skill)을 먼저 읽고 파일을 열어 실제 값에 접근한다. 이 경우 Step 2는 "실측 프로파일링"으로 진행한다.
- **사용자의 설명(텍스트)만 있는 경우** → 실제 값이 없으므로 "추정 프로파일링"으로 전환한다. 문장에서 컬럼 구조(어떤 축이 범주형/시간/수치형인지)를 역으로 추론하고, 규모 지표(카테고리 개수 등)는 사용자가 언급한 대략치나 정성적 표현("많다/적다")에 의존한다. 구조 추론이 애매해서 추천 차트가 크게 갈리는 지점이 있다면, 그때만 한 가지 확인 질문을 한다(예: "출처 종류가 대략 몇 개 정도 되나요?"). 무리하게 여러 질문을 던지지 않는다.

세부 판별 항목과 방법은 `references/scan-procedure.md` 참고.

### Step 2. 데이터 스캔

`references/scan-procedure.md`의 Step A(컬럼 프로파일링) → Step B(구조 태그 판별) → Step C(규모 지표 산출)를 순서대로 수행한다. 결과로 아래와 같은 **Data Profile**을 내부적으로 정리한다 (사용자에게 장황하게 보여줄 필요는 없고, 다음 단계 판단의 근거로만 사용):

- 구조 태그 목록 (예: 시계열, 노드-엣지, 계층 등 — 복수 가능)
- 규모 지표 (범주 개수, 시리즈 개수, 노드 개수, 계층 깊이 등 — 정성적 판단 포함 가능)
- 구성/비율(Composition) 후보 여부 (확정 아님, 플래그만)

### Step 3. 목적 문장 해석

사용자가 준 목적 문장을 읽고, `references/mapping-rules.md`에 정리된 11개 **의도 축(Narrative Intent)** 중 어떤 신호가 강하게/약하게 들어있는지 판단한다. 이 의도 축 목록은 사용자에게 노출하는 선택지가 아니라 Claude 내부의 채점 기준표임을 항상 기억한다. 한 문장에 여러 의도가 섞여도 정상이며, 그럴 때는 주 의도와 부 의도를 구분한다.

### Step 4. 교차 매핑

`references/mapping-rules.md`의 규칙표를 사용해:
1. Step 2의 구조 태그가 각 의도 축의 "필수 조건"을 만족하는지 확인 → 불만족하면 해당 의도의 차트 후보는 전부 탈락
2. 통과한 후보 중, Step 2의 규모 지표(보조 조건)로 세부 차트를 좁힌다
3. 부 의도는 별도 차트로 만들지 말고, 가능하면 색상/정렬/두께 등 인코딩 요소로 주 의도 차트에 흡수시킨다 (예: Sankey의 링크 두께가 비중을 함께 표현)

### Step 5. 레이아웃 필터

`references/chart-catalog.md`의 "가로형 적합도" 표를 기준으로, Step 4에서 나온 후보들을 재평가한다. 원형/방사형 계열(Pie, Donut, Radar, Sunburst, Gauge)이 후보에 남아있다면, 동일 정보를 전달하는 와이드 친화 대체 차트(Stacked Bar, Parallel Coordinates, Treemap, Bullet Chart 등)가 있는지 반드시 먼저 확인하고, 있다면 그쪽을 승격한다.

### Step 6. 추천 + 시각화

- 최종 후보 1~2개를 **왜 이 문장의 의도와 이 데이터 구조에 맞는지, 왜 와이드 레이아웃에 적합한지**를 함께 설명하며 제시한다. 차트 이름만 던지지 않는다.
- 카테고리/노드/시리즈 개수가 많아 라벨 겹침이나 복잡도가 우려되는 경우, 이 시점에 "Top N + 기타로 묶었습니다" 같은 조정 사항을 사후 코멘트로 알려준다 (사전에 차단하지 않는다).
- 실제 시각화는 Visualizer(`mcp__visualize__show_widget`, 사전에 `read_me`로 `chart`/`diagram` 모듈 로드) 또는 `chart_display_v0`(단순 line/bar/scatter인 경우) 중 데이터 형태에 맞는 쪽을 사용해서 인라인으로 렌더링한다. Sankey, Treemap, Funnel, Parallel Coordinates, Waterfall처럼 표준 차트 도구 스펙 밖의 차트는 Visualizer의 `diagram`/`chart` 모듈을 사용한다.
- 여러 후보를 비교해서 보여주고 싶을 때는 후보별로 텍스트 설명 → 시각화를 번갈아 배치한다(한 번에 여러 개를 몰아서 렌더링하지 않는다).

## Reference 파일

- `references/data-patterns.md` — 데이터 성격(종류) 15가지 목록과 판별 힌트
- `references/chart-catalog.md` — 차트 유형 25종 목록, 적합한 데이터 성격, 가로형(와이드) 적합도
- `references/mapping-rules.md` — 11개 의도 축별 필수조건/후보/보조조건 매핑 규칙, 다중 의도 처리 원칙
- `references/scan-procedure.md` — Step A~D 데이터 스캔 절차 상세 (컬럼 프로파일링, 구조 판별, 규모 지표, 파일/설명 분기)

각 파일은 필요한 시점에만 열어서 참고한다. 예를 들어 목적 문장을 해석하는 단계에서는 `mapping-rules.md`만 보면 되고, 스캔 절차를 수행할 때는 `scan-procedure.md`만 보면 된다.
